Verifex

Verifex is a small Solana program that checks one on-chain fact about an agent and, if the check passes, issues a seven-day credential through Referee, so a DvP trade can only settle for parties the chain has vouched for.

Devnet only. Unaudited. Independent project, not affiliated with or endorsed by the Solana Foundation or J.P. Morgan. Every row below carries a signature you can check yourself.

What it checks

Each Verifex instruction runs one check, then calls Referee's issue_credential, signing as Verifex's own program-derived address. Today there are two instructions, so two checks.

verify_and_issue

The agent's program must have no upgrade authority, so its code can no longer be changed.

Otherwise it refuses with AgentNotImmutable (6002).

verify_outcome_and_issue (“Verifex Core”)

A commitment on TrustRail Core must be Passed and verified, and its executor must be the credential's subject.

Otherwise it refuses: BadCommitment (6003), CommitmentNotPassed (6004) or SubjectNotExecutor (6005).

Why it exists

DvP's CreateDvp needs only the payer to sign. The two parties and the settlement authority do not, so something has to decide who may settle. On devnet, that is Referee: its program-derived address is the settlement authority, and its settle step needs a valid credential for both parties. Verifex is the program that issues those credentials. If a credential is missing or expired, the trade never settles, and the parties can walk away through DvP's own Reject or Reclaim.

TrustRail Core

TrustRail Core: barebones, devnet only devnet only

TrustRail Core is a devnet-only fork of my separate TrustRail project. I made it for the Referee capstone so that Verifex has a real outcome to check. It is barebones: the swap behind it is a 1:1 stand-in, and its pass check compares an output balance with a minimum, so a plain donation could satisfy it. Treat it as proof the wiring works, not as a security guarantee. The program (58t4gi88MNSURkwN6GuGugmXWPFqAT6s9pB56Srx4Bez) is upgradeable by my wallet. TrustRail itself is unchanged.

The patch, in the Referee repo

Limits

  • This is a demonstration of the path from check to credential to settlement. It is not a security guarantee, and it is not KYC.
  • Devnet only. Unaudited.
  • Both Verifex and Referee are upgradeable by my wallet, which is a trust assumption.
  • The first check shows only that a program can no longer be upgraded. It says nothing about what the program does.
  • The second check trusts TrustRail Core's Passed status, which is a weak gate.
